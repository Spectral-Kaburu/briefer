
## Phase 10: Knowledge sources for ask mode (Wikipedia, Stack Exchange, optional DDG instant answer)

**Where this comes from.** Phase 9's ask mode answers only from pages found by `ddgs` text search. For two kinds of question that is the slow, noisy route: encyclopedic ("what is X", "who was Y", "history of Z") and developer ("why does X raise Y", "how do I do X in Python"). Both have a free, structured, citable source: the Wikipedia REST API and the Stack Exchange API. A third source, the DuckDuckGo Instant Answer endpoint (`api.duckduckgo.com`), is unofficial and often empty; it is probed first and kept only if the probe shows it earns its place.

**Goal.** (1) Add never-raising adapters for Wikipedia and Stack Overflow that return ready-made passages with no page fetch. (2) Let ask mode run them **concurrently with the web search**, under the existing deadline, and merge their passages into the numbered evidence. (3) Keep `-r` (research mode) and briefing mode byte-for-byte unchanged.

**Dependencies and order.** Do not start until **T9.8 and T9.9 are ticked** (ask mode must be proven against the real world first, or this phase builds on unverified ground). Order: T10.0 → T10.1 → T10.2 → T10.3 → T10.4 → T10.5 → T10.6 → T10.7 → T10.8 → T10.9.

Skills: `ruthless-review` for every **[review]** task in this phase, `fix-loop` for every defect a review raises, `superpowers:test-driven-development` for every code change, `superpowers:systematic-debugging` when a test fails twice, `superpowers:verification-before-completion` before every tick, `superpowers:requesting-code-review` for **[review]** tasks, `simplicity-first` (if installed) for T10.1 and T10.5 so nothing is built beyond what is written here. Never invoke the `firecrawl:*` skills. Every adapter test uses `respx`; the isolation guard stays on. No new dependency: `httpx` and the stdlib `html.parser` are enough.

- [ ] **T10.0** Probe and record, read-only, no code changes. With plain `curl` (no pipes, no escalation) probe and record the exact response shapes in a new `NOTES-APIS.md` §5, with source URLs: (a) Wikipedia `GET https://en.wikipedia.org/w/api.php?action=opensearch&search=<q>&limit=3&profile=fuzzy&format=json` (a four-element array) and `GET https://en.wikipedia.org/api/rest_v1/page/summary/<title>` (the fields `type`, `title`, `extract`, `content_urls.desktop.page`; note the value of `type` for a disambiguation page); (b) Stack Exchange `GET https://api.stackexchange.com/2.3/search/advanced?q=<q>&site=stackoverflow&accepted=True&sort=relevance&order=desc&pagesize=3&filter=withbody` (note `items[]`, `accepted_answer_id`, `quota_remaining`, `has_more`, and that bodies are HTML) and `GET .../2.3/answers/<ids>?site=stackoverflow&filter=withbody`; (c) `GET https://api.duckduckgo.com/?q=<q>&format=json&no_html=1&skip_disambig=1&no_redirect=1`, using **ten** test queries (five entity-like such as "python programming language", five question-like such as "what is the current python version") and tabulating how many return a non-empty `AbstractText` or `Answer`. Also note the User-Agent policy of each host. The three hosts (`en.wikipedia.org`, `api.stackexchange.com`, `api.duckduckgo.com`) must be allowed by the owner in the sandbox settings; if one is refused, do **not** escalate: log it in `DENIED.md`, put the exact curl in `BLOCKED.md`, and leave this box unchecked (the later tasks then stay blocked, because their fixtures must come from real shapes). *Accept*: §5 lists every endpoint, parameter and field the later tasks use, plus the DDG hit table.

- [ ] **T10.1** The shared seam. In `knowledge/base.py` (new package, no I/O) define `Passage(text, title, url, domain, license, author)` and a `KnowledgeSource` protocol: `name`, `badge` (`WIKI`, `SO`, `DDGA`), `async lookup(query, *, limit) -> list[Passage]`. The contract, written in the docstring and enforced by a shared parametrized test that every adapter must pass: **never raises** (connect error, timeout, non-2xx, bad JSON, unexpected shape, HTTP 429 → `[]`, logged at DEBUG), honours its configured timeout, sends a generic `User-Agent` (`briefing/<version>`; **never an email address or a real name**), and returns text already stripped of HTML **and of control characters** (C0/C1 controls and ANSI escape sequences are removed, because API text is printed to a terminal and written to logs; newlines and tabs are kept). Add config `knowledge: {enabled: true, wikipedia: true, stackexchange: true, ddg_instant: false, timeout_s: 5, user_agent: ""}`; an empty `user_agent` means the generic default. *Accept*: model and protocol tests, the shared contract test parametrized over a fake adapter, config default and override tests, `test_shipped_example_config_loads` still green.

- [ ] **T10.2** `knowledge/wikipedia.py`. Opensearch (fuzzy, `limit=3`, language from the `search.region` suffix, falling back to `en`), then the REST summary of the first hit whose `type` is not disambiguation (skip to the next; return `[]` if all are). `Passage.text` is the summary `extract`, `license` is `CC BY-SA 4.0`, `url` is the canonical page, accepted only if it is `https` on a `*.wikipedia.org` host (anything else is dropped, so an API response can never make us print or follow a foreign link). A typo query ("verstion") must still resolve through the fuzzy profile (this is a test of our parameters being sent, since respx cannot test Wikipedia's matching; record that limit in the test's docstring). *Accept*: respx tests for success, fuzzy parameter present, disambiguation skipped, empty opensearch, redirect title, 404 on summary, 429, 500, timeout, malformed JSON, non-dict shape, and a non-English region mapping to the right host.

- [ ] **T10.3** `knowledge/stackexchange.py`. Search advanced (`accepted=True`, `site=stackoverflow`, `filter=withbody`, `pagesize=3`), then one batched call for the accepted answers of the returned questions. A `Passage` is the question title plus the **accepted answer's** text (HTML → plain text with `html.parser`; keep `<pre><code>` blocks but cap each at 600 characters; drop images), `author` from `owner.display_name`, `license` `CC BY-SA 4.0`. Key from env var named by `knowledge.stackexchange.key_env` (default `STACKEXCHANGE_KEY`), read at call time only, optional, and added to the `SecretFilter` set so it never reaches a log or `--json`. Track `quota_remaining` from each response: at or below a configured floor (default 20) the adapter returns `[]` without calling and logs why; on a `backoff` field in the response it honours the value for the rest of the process. *Accept*: respx tests for success with and without a key, no accepted answer, `backoff` honoured, quota floor, 400 (bad filter), 429, 500, timeout, malformed JSON, HTML-to-text fixtures (entities, nested code, a script tag stripped, an image dropped), and a test that the key never appears in any log record. **[review]**

- [ ] **T10.4** `knowledge/ddg_instant.py` (**conditional on the T10.0 hit table**). If fewer than 3 of the 10 probe queries returned a non-empty answer, do not build the adapter: tick this box with a one-line note, record the hit table and the decision in `DECISIONS.md`, and leave `ddg_instant: false` documented as "probed, not worth it". Otherwise build it: `AbstractText` (and `Answer` when present) as a `Passage` with `AbstractURL` and `AbstractSource` for attribution, `skip_disambig=1`, `no_html=1`, empty abstract → `[]`. *Accept*: either the written decision, or respx tests for abstract, answer-only, empty, disambiguation and the shared contract test.

- [ ] **T10.5** `knowledge/route.py`: a pure `choose_sources(question) -> list[str]` returning source names. Encyclopedic cues ("what is/are", "who is/was", "define", "history of", "when was", "meaning of", "capital of") select Wikipedia; developer cues (an exception or error name, a traceback fragment, "how do I … in <language>", a language or framework name from one editable constant, backticks, a `::` or `()`) select Stack Overflow; a news-mode question (the same `detect_mode` the search uses) selects neither, because both sources lag the news; no cue selects nothing and ask mode behaves exactly as in Phase 9. A false positive costs one cheap concurrent request, so keep the rules short and the lists editable constants rather than growing heuristics. *Accept*: a parametrized table of at least 25 synthetic questions with expected selections, including typos, a question that matches both, and "latest python version" selecting neither.

- [ ] **T10.6** Wire into ask mode. In `ask.py`, start the chosen adapters as tasks **at the same moment as the web search**, under the same overall deadline; a slow or failed adapter is cancelled and contributes nothing, and never delays the answer past `deadline_s`. Merge rules: knowledge passages are numbered **before** web sources (they are the strongest evidence for their question types); they do not consume the `pages` fetch slots but do count against `evidence_chars`; at most **one passage per adapter** (the best), so the prompt stays small; if a web result's normalized host is `wikipedia.org` (or `stackoverflow.com`) and the adapter already supplied that site, drop the web result rather than number it twice. The prompt is unchanged except that each source block carries its badge and license, and the existing "name the sites that disagree" instruction now covers a Wikipedia-versus-web conflict. Source text still goes inside the delimited block with the closing delimiter stripped, and API text is treated as untrusted exactly like page text (a Stack Overflow answer is user-written). No key and no model: `used_llm=False` as before, with the knowledge passages shown first. *Accept*: fake-adapter tests for numbering order, concurrency (a slow adapter does not delay a fast search), the deadline cancelling an adapter, one-passage-per-adapter, host de-duplication, an adapter returning a poisoned passage ("ignore previous instructions" plus the fake closing delimiter) staying inside its block, all adapters failing leaving the Phase 9 answer untouched, and `knowledge.enabled: false` giving byte-identical output to Phase 9. **One CLI-level test goes through the real `_ask` seam with a fake adapter and asserts it was called; sabotage the wiring and watch it fail.** **[review]**

- [ ] **T10.7** UI and JSON. Badges `WIKI`, `SO` and (if built) `DDGA` beside `LOCAL`, `API`, `SNIPPET`; the footer counts them ("1 wiki · 1 so · 2 local"); a source line for a CC BY-SA passage shows the license and, for Stack Overflow, the author. `--json` sources gain `license` and `author` (empty for web sources). Flag `--no-knowledge` on `ask` and the group shorthand's config key, mirroring `--no-api`. `-r` output is **unchanged**; a test pins that. *Accept*: snapshot tests (`Console(record=True, width=100)`) for an answer with a wiki source, an SO source and both; `--json` shape test; `--no-knowledge` test; the `-r` pin test; `scripts/render_samples.py` gains two scenarios and `docs/sample-output.txt` is regenerated, not hand-edited.

- [ ] **T10.8** Live tests. Add `@pytest.mark.live` tests for the real Wikipedia and Stack Exchange adapters (one query each, so the quota is barely touched), skipping rather than failing on 429, an exhausted quota or a refused host, the same way the Firecrawl live tests treat a degraded instance. A third live test runs `ask` end to end for "what is the python programming language" with no model key and asserts the first source is `WIKI`. *Accept*: `make live` passes or skips with a stated reason; sabotage one adapter's host and confirm its live test fails against a healthy service.

- [ ] **T10.9** Docs and close-out. README: a "Knowledge sources" section (what each source covers, when each is chosen, `knowledge:` config, the optional Stack Exchange key and the higher quota it buys, `--no-knowledge`, the license and attribution behaviour); `config/briefing.yaml.example` and `docs/sample-output.txt` updated; `NOTES-APIS.md` §5 and the `DECISIONS.md` entries (one per merge rule in T10.6) written. `make check` green; whole-repo review of the Phase 10 diff with explicit questions: can any adapter raise or block past its timeout; does any path print or log a key; is an email address or real name sent in any header; can source text from an API escape its delimiter; does `-r` or briefing mode change at all; does the Stack Exchange quota floor really stop calls. Then the `verifier`. Add a Phase 10 summary to `PROGRESS.md` ending with "What the owner must still do": optionally register a free Stack Exchange key and set `STACKEXCHANGE_KEY`, judge a few real `briefing -a` answers for Wikipedia and Stack Overflow questions, and decide whether `-r` should also get a knowledge card.

Out of scope for this phase (owner's call, do not build): Reddit, X/Twitter and Quora (the first is rate-limited and wall-prone, the other two are closed to free access), the `ddgs` `books()` engine, other Stack Exchange sites, Wikidata and non-Wikipedia wikis, caching of API responses, knowledge cards in `-r` or briefing mode, automatic routing of a bare question to ask mode, and any new LLM provider.

## Phase 11: Ruthless whole-repo audit (after Phase 10)

**Where this comes from.** Ten phases of green tests have repeatedly hidden defects the tests could not see: a guard whose docstring promised an exemption it did not implement, a log line that was decided, ticked and never written, precedence tests that passed with the order reversed. Phase 11 hunts that whole class on purpose, across the **entire** repo, in rounds, until a round finds nothing new. It adds no features.

**Method.** Four project skills (installed by `apply.sh` into `.claude/skills/`) and one read-only agent (`.claude/agents/slice-auditor.md`) do the work; read each `SKILL.md` before using it.

- `ruthless-audit`: the orchestrator. Maps the repo, fans out `slice-auditor` agents per slice, runs mechanical sweeps, verifies every finding against the cited line, keeps the ledger in `AUDIT.md`, and recurses: each round re-audits what the previous round changed plus its dependents, until a round adds no new P0 to P2 finding or five rounds have run. It never edits code.
- `fix-loop`: fixes one finding at a time: reproduce red, smallest fix, green, **sabotage (revert the fix and watch the test fail again)**, full `make check`, then hunt the same bug's siblings.
- `mutation-sweep`: audits the tests themselves by mutating the code under them and demanding red; every survivor is a test that cannot fail.
- `ruthless-review`: adversarial review of a diff or phase, read-only, ending in a PASS or FAIL verdict. It also checks every ticked claim in `PLAN.md`, `PROGRESS.md` and `DECISIONS.md` against the code.

**Dependencies and order.** Start only after **Phase 10 is ticked** (or the owner says to audit earlier). Order: T11.0 → T11.1 → T11.2 → T11.3 → T11.4 → T11.5 → T11.6 → T11.7 → T11.8 → T11.9. Skills `superpowers:verification-before-completion` before every tick and `superpowers:systematic-debugging` when a fix fails twice. Never run `briefing run` through the real entry point, never run `voice-tts`, no network outside `@pytest.mark.live` and the allowed smoke forms, no sandbox escalation.

- [ ] **T11.0** Baseline and map. Record in `AUDIT.md`: the commit, `make check` counts, `make live` result (or why it was skipped), and an inventory table of every file under `src/`, `tests/`, `scripts/`, `systemd/`, `config/`, `docs/` with line counts and its test file. Confirm the four skills and `slice-auditor` are present (`ls .claude/skills .claude/agents`); if one is missing, stop and write it to `BLOCKED.md`. *Accept*: `AUDIT.md` exists with the baseline and inventory, and the tree is clean.

- [ ] **T11.1** Mechanical sweeps. Run every sweep in `ruthless-audit/lenses.md` section "Mechanical sweeps" and enter each hit that is a real problem in the ledger with file:line evidence (a hit that is fine gets a one-line "checked, fine" so the next round does not redo it). *Accept*: every sweep has a recorded result, even if empty.

- [ ] **T11.2** Round 1 slice audit. Partition the repo into slices of at most about 600 source lines, each paired with its tests; run one `slice-auditor` per slice in parallel; verify every returned finding against its cited line (a quote that does not match is discarded and counted as a hallucination); merge and de-duplicate. *Accept*: the ledger holds every verified finding with severity, confidence and lens, and the round's counts are written.

- [ ] **T11.3** Test truth. Run `mutation-sweep` on the twelve riskiest units: `fetch/router.py`, `fetch/errors.py`, `whitelist.py`, the schedule and audio gates, dedup TTL, `config.py` discovery, the `SecretFilter`, the `ask.py` deadline and delimiter stripping, `extract.py` cleaning, the three knowledge adapters' never-raise contract, and `tests/conftest.py`'s guard. Every surviving mutant becomes a ledger finding (lens L8). *Accept*: each unit has a survivors table, and no unit is skipped without a written reason.

- [ ] **T11.4** Fix the P0 and P1 findings with `fix-loop`, in severity order, one finding per change. Anything that needs an owner's decision (the "out of scope, owner's call" items from earlier phases, a behaviour change to a public flag, a dependency) goes to `BLOCKED.md` with the exact question and is **not** decided here. *Accept*: every P0 and P1 is fixed (with a test that was seen failing, then seen failing again under sabotage) or sits in `BLOCKED.md`, and `make check` is green.

- [ ] **T11.5** Fix the P2 findings the same way. P3 findings are fixed only when the change is a single line with no behaviour change; otherwise they stay in the ledger as P3. *Accept*: as T11.4 for P2.

- [ ] **T11.6** Recurse. Run `ruthless-audit` rounds 2 to 5: each round's scope is the files changed since the previous round started plus their one-level reverse-dependency closure and their tests; each ends with `make check`; stop when a round adds no new P0 to P2 finding (the stop is stated as "no findings in round N under these lenses, scope covered: ...", never as "clean") or after round 5, whichever is first. *Accept*: a rounds table in `AUDIT.md`, with counts per round, ending at a stated stop condition.

- [ ] **T11.7** Claims against code. Check every claim a reader would trust: each ticked box in `PLAN.md` (does the thing it says exist, with the test it names), each `PROGRESS.md` and `DECISIONS.md` verdict, the README against `briefing --help`, `briefing research --help`, `briefing ask --help` and `briefing config`, `config/briefing.yaml.example` against `config.py` defaults (every key read somewhere, every key defined), `docs/sample-output.txt` against a fresh `scripts/render_samples.py` run, and dead links. A claim that is false is fixed in the code if the claim was the intent, in the doc if the code was the intent, and logged when it is unclear which. *Accept*: a claims table in `AUDIT.md` with a verdict per claim.

- [ ] **T11.8** Real-world re-smoke. With the allowed forms only (`BRIEFING_STATE_DIR=.smoke-state .venv/bin/briefing ...`, always `--no-api`, no pipes, no redirects, no escalation): `status`, `config`, `research "latest breaking news in kenya" --no-api -n 5 --plain` and `--json`, and `ask` for one encyclopedic, one developer and one news question with `--no-api`, with and without a model key as available. Read the output as the user would. Every defect gets a synthetic-fixture test first, then goes through `fix-loop`. If the network is refused, log the host in `DENIED.md`, write the exact commands in `BLOCKED.md`, and leave this box unchecked. *Accept*: counts and a defect list in `PROGRESS.md`, every fixed defect has a test.

- [ ] **T11.9** Close-out. `make check` green; `make live` if reachable; a final `ruthless-review` of the whole Phase 10 and Phase 11 diff with these explicit questions: does anything still catch `BaseException` or swallow `CancelledError`; can any adapter or fetch exceed its timeout; can any key, real name or email reach a log, a header, `--json` or a file; can untrusted text escape its prompt delimiter, inject Rich markup, or put control characters on the terminal; can any test spawn a process or open a socket; is any ticked claim false. Then the `verifier`. Write a Phase 11 summary in `PROGRESS.md` ending with "What the owner must still do": the `BLOCKED.md` decisions, the keys, and everything left as P3 or unverified. *Accept*: review PASS, verifier VERIFIED, summary written.

Out of scope for this phase (owner's call, do not do): new features, new dependencies or version bumps, style-only refactors, rewriting a module that works, renaming or removing a public CLI flag, and the earlier phases' owner's-call items (D7 gate behaviour, `detect_mode` keyword false positives, footer wrapping below 60 columns).
