## Phase 9: Answers, not page dumps (from the owner's first real run, 2026-11-03)

**Where this comes from.** The owner's first real `briefing -r "What is the current python verstion"` ran end to end (10 pages, all local, 21.6s) but exposed problems no mock could. Defect catalogue (patterns only, never paste the third-party text):

- **D1** Setext underlines and rules leak into summaries (`=====`, `-----`).
- **D2** Markdown images and link wrappers leak (`![alt text](https://… "title")`, `[![…](…)](…)`), including runs of them.
- **D3** Page chrome leaks: "Skip to main content", "Back to top", "View this page", "Edit this page", "Mark as Completed", "Share", "Table of Contents", "Remove ads", "Reading time estimate", "N Comments".
- **D4** Concatenated navigation tokens with no spaces (long digit/dot runs such as a version list, "» dev (3.16)3.15.23.14…").
- **D5** Flattened tables repeat near-identical segments ("Version: X Status: Y Life: …" many times).
- **D6** A summary with no sentence terminators is not length-capped (one card ran ~30 lines).
- **D7** A card's heading was unrelated to its page (a code/type-checker changelog line shown as the title of a Python 3.11 release page).
- **D8** The cards do not answer the question: the summary is the first paragraph, which is usually an intro, so the answer is buried or absent. Sources also disagreed (one site labelled an older release "latest stable" while others said a newer one had shipped), which extraction cannot resolve.
- **D9** The same host can fill several of the ten slots, and a typo in the query ("verstion") would defeat any naive term matching.

**Goal.** (1) Make `-r` cards clean and relevant. (2) Add an **ask mode** (`briefing -a "question"`, also `--ask` and `--instant`, plus an `ask` subcommand) that answers directly in a few sentences with numbered sources, fast, grounded only in what it fetched. (3) Make the Gemini key a first-class, visible, never-leaked setting.
